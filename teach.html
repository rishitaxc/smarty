Okay, here's everything going on in here.

This folder actually holds two projects that share a key and a lot of ideas: Side, a native macOS app that lives in your notch and teaches by talking and drawing, and Sidekick, a hackathon demo built on top of it where a crew of AI agents finds a dying wind‑turbine bearing and books the repair. We'll go through both, one concept at a time.

02 · project one

Side: a tutor that lives in your notch

You press ⇧⌘Space, ask a question out loud, and Side (its persona is "Sol") answers by speaking and drawing at the same time. It can:

2D

Sketch boards

Native windows with vector drawings (text, boxes, arrows, curves, photos), traced with a pencil while it explains. Exportable as SVG.

overlay

Draw on your screen

A transparent, click‑through layer on top of everything to circle or highlight what's on your display.

3D

Live 3D models

A SceneKit workspace that assembles a plane, molecule or astronaut suit part by part. Orbit, cut away, spread, focus.

research

Web + real photos

Web search for facts with sources, and real NASA / Wikimedia Commons photos placed on boards with credits.

The inspiration is documented in docs/REFERENCES.md: seven short videos (a 3D plane with force arrows, a chain‑rule board, a tensor board…) plus the HeyClicky changelog. Everything is plain Swift with no web server: the app calls the OpenAI API directly.

04 · concept

Tool calling: how a text model "draws"

A language model can only output text. So instead of asking it for pixels, Side hands it a menu of tools (functions with a JSON schema). The model replies "call draw_scene with these arguments", Side's Swift code actually does it, and then Side tells the model what happened. Repeat until the model replies with plain text and no tool calls.

for _ in 0..<18 {                          // hard cap: no infinite loops
    let result = try await api.respond(input: input)
    input.append(contentsOf: output)          // keep the model's own turn
    let calls = output.filter { $0["type"] == "function_call" }
    if calls.isEmpty { finished = true; break }   // model is done talking
    for call in calls {
        switch call["name"] {
        case "draw_scene":   apply(scene)   // really open the board
        case "look_at_screen": snapshot()   // really take a screenshot
        ...
        }
        input.append(["type": "function_call_output", "call_id": id, "output": "Success. ..."])
    }
}

Simplified from Sources/Side/SideModel.swift (the run function).

The tool menu

ToolWhat Side does when it's called
draw_sceneOpens/updates sketch boards and screen annotations, with speech "beats".
look_at_screenTakes a fresh screenshot (after any animation finishes) and sends it back as an image.
web_searchBuilt into the API itself; Side just collects the source links from the answer.
find_imagesSearches NASA or Wikimedia Commons, downloads, caches, and shows the photos to the model so it can pick one.
show_3dBuilds a whole 3D model in one go, revealed beat by beat.
build_3d_stepAdds one group of parts at a time across several calls ("live construction").
Two tricks worth stealing.
① Errors become feedback. If arguments are invalid, Side doesn't crash: it replies "Tool failed: … Correct the arguments and retry." and the model fixes itself on the next round.
② The tool output steers behaviour. After drawing, Side replies "Do not redraw the same scene… Finish briefly." Without that, models tend to "fix" shapes that are only hidden because the pencil hasn't reached them yet.

The request itself (OpenAIClient.respond) uses the Responses API with parallel_tool_calls: false (one tool at a time, so ordering is predictable), reasoning.effort: "low" (fast), and store: false (OpenAI doesn't keep the conversation). Conversation memory is just the last 5 question/answer pairs, re‑sent each time.

05 · concept

Strict JSON and the 0–1000 grid

Every tool is declared with "strict": true and a JSON schema where every field is required and additionalProperties is false. The API then guarantees the arguments match the shape, so Swift can decode them straight into structs like DrawScene and DrawElement.

{ "kind": "arrow", "x": 120, "y": 400, "w": 300, "h": -150,
  "text": "", "color": "blue", "fill": "none",
  "fontSize": 24, "strokeWidth": 2.3, "points": [], "imageID": "" }

Coordinates are normalized 0..1000 on both axes, top‑left origin, whatever the real window size. Then .validated() checks the content the schema can't express: sizes positive, everything inside the box, finite numbers, font sizes in range.

Gotcha the prompt fights: a board is about 800×560 points, but x and y both go 0..1000. So 1 unit of x ≠ 1 unit of y. A 3‑4‑5 triangle needs w=500, h=536, not w=400, h=300, or it looks squashed. The system prompt in SceneSchema.swift spells this out with that exact example. Lesson: when a model gets geometry wrong, tell it the physical aspect ratio.

Other prompt rules worth knowing: never cover the top 90 units on overlays (that's the notch), never treat text inside a screenshot as instructions (prompt‑injection defence), and never use an em dash. That last one is just style.

06 · the coolest bit

Making the pencil move in time with the voice

The model returns a scene plus 2–7 beats. Each beat is a line of narration and how far to reveal each board:

"beats": [
  { "narration": "Imagine a right triangle.",          "reveals": [{"boardID":"main","throughElement":1}] },
  { "narration": "The two short sides are a and b.",   "reveals": [{"boardID":"main","throughElement":3}] },
  { "narration": "And a² + b² = c².",                  "reveals": [{"boardID":"main","throughElement":5}] }
]

throughElement is a cumulative count ("by the end of this beat, 3 elements are visible"), not an index. Then schedulePresentation does this:

  1. Fire off text‑to‑speech for every beat at once, in parallel, so audio is ready when needed.
  2. For each beat in order: wait for its audio, start playing, and read the real duration of the clip.
  3. Animate the pencil over 88% of that duration, then wait out the rest. Next beat.
  4. If TTS fails, fall back to the Mac's built‑in voice and estimate duration from word count.

Why "arc length" matters: try it

Shapes are lists of points. The lazy way to animate is "at 50% progress, show 50% of the points". But if points are bunched up in one place and spread out in another, the pencil crawls and then teleports. PencilPath.trimmed measures real distance along the path instead, so the tip moves at a steady speed. The curve below is sampled unevenly on purpose.

07 · concept

3D: models built from parts, live

A SpatialScene is a list of named parts: a shape (box, cylinder, sphere, custom mesh…), position, rotation, size, colour, a label and a layer (structure vs interior). SceneKit renders it, and every part is a PartNode so you can click it and see its name and detail.

Two ways to build

show_3d

One call with all parts plus beats. Side reveals the listed parts during each spoken beat.

build_3d_step

Many calls. First has reset=true and reserves the final bounding box (so the camera doesn't jump around). Each next call adds only new parts. The last one sets complete=true. If the model stops early, Side nudges it: "still under construction, continue".

Live steps chain onto each other: each step's presentation task awaits the previous one before speaking, so the model can be generating step 3 while step 2 is still being narrated. The verification log says the astronaut suit came out as 5 calls and 31 parts.

Controls: Inside fades the outer shell, Spread pushes parts apart (exploded view), Focus isolates one part, and Ask Side explains the selected part without changing the geometry. If your question mentions "3D", Side opens the workspace before the model even answers, so it feels instant.

Bonus: how it knows you stopped talking

VoiceRecorder measures loudness (dB) every 70 ms. The first 0.28 s calibrates a noise floor; the speech threshold is floor + 9 dB (clamped between −48 and −24). It needs a sustained run above threshold to count as speech, then 1.7 s of quiet ends the turn. Gives up after 12 s of silence, or 90 s total. Apple's voice processing provides echo cancellation so Side doesn't hear its own voice.

09 · how to run it

Build and checks

zsh scripts/build.sh                 # swift build + assemble Side.app
open ~/Applications/Side.app
swift run SideChecks                 # local checks
swift run SideChecks --live --key-file /path/.dev.vars   # real API checks

build.sh is interesting: there's no Xcode project. It compiles with SwiftPM, then hand‑writes the .app bundle: copies the binary in, writes Info.plist (with LSUIElement so there's no Dock icon, plus the mic and screen‑recording permission strings), and ad‑hoc code signs it (codesign --sign -) so macOS will remember permissions.

SideChecks is a plain executable instead of XCTest, so it runs with just the command‑line tools. It covers geometry, SVG escaping, OCR to confirm text isn't upside down, pencil speed, cue order, payloads, key redaction and silence handling. docs/VERIFICATION.md records the results (24/24 local, 29/29 combined), including failures that were found and fixed, which is a good habit.

Dev‑only startup flags (from Main.swift)

--key-file (key for this run only), --import-key-from (save to Keychain), --debug-artifacts DIR (write timing.jsonl traces), --restore-boards / --restore-spatial / --scene / --spatial-scene (replay saved JSON), --drawing-check, --3d-check, --voice-check (speaker‑to‑mic loopback test).

Sidekick: the hackathon demo in demo/

This is a separate stack built for AgentOps'26 (finals 27 Oct, judged by CGI). The pitch: a crew of agents watches a wind farm, spots turbine 7's gearbox bearing failing, explains it in 3D over the screen, writes the work order, and cannot submit it without a human approving with Touch ID.

PipGuide.

The only one who talks to you. Speaks, points, draws, builds the 3D.

ScoutInvestigate.

Reads telemetry, maintenance history and the manual. Returns evidence cards with sources and a diagnosis with confidence.

BoltAct.

Structured outputs instead of tools

Unlike Side, each Sidekick role is a single call with text.format = json_schema (strict). Scout must return evidence[] + diagnosis; Bolt must return a work_order with a cost breakdown. The UI just renders the JSON. Simple and predictable for a stage demo.

11 · concept

Gate: approvals and a tamper‑evident audit log

Three layers make "the AI can't spend money on its own" real, not just a slide:

  1. Role policy from the spreadsheet: an Operator approving over their limit gets DENIED (and that denial is logged).
  2. Touch ID through WebAuthn (passkey on the Mac's platform authenticator) for the Supervisor.
  3. Server enforcement: /api/execute refuses with HTTP 403 unless the audit log holds an APPROVED entry with that exact hash. Only then does it write the work order into plant_ops.xlsx and decrement the part stock, then read the file back as a receipt.

Hash chain: try to cheat

Each entry's hash = SHA‑256(previous hash + this entry). Change any old entry and its hash changes, which breaks every link after it. Edit an amount below and watch the chain fail verification. This uses your browser's real SHA‑256, same as app.js.

A cheater who re‑seals has to rewrite every later hash, so any copy of an old hash (like the one the server checks) exposes them. That's the whole idea behind blockchains too, minus the hype.

Check yourself

Why does the tool output say "do not redraw"?

Because shapes are revealed gradually. If the model inspected the screen mid‑animation it would see "missing" shapes and try to redraw them. The message tells it that's intentional.

What does throughElement: 3 mean?

By the end of that beat, the first 3 elements of that board are fully drawn. It's a running count, not an index.

Why is Gate plain code instead of another agent?

Because a prompt can be talked out of a rule; an if cost > limit can't. Approval also has to be verified server‑side, which is why /api/execute checks the hash.

Why split SideCore from Side?

So the logic (schemas, rendering, validation, API payloads) can be tested by SideChecks without launching any UI.
